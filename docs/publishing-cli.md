# 上架命令规范

状态：prepare / preview / validate / status 已实现；publish / resume / bundle 仍为待实现设计。示例 ID、文件和计划编号均为示意；实际操作见 [本地使用说明](local-development.md)。当前可直接通过 prepare --manifest 批量准备一个审核计划。

## 1. 命令入口与环境

在仓库根目录通过 `npm run book -- <子命令>` 调用同一个 TypeScript CLI。CLI 接受参数数组，不把书名、模型名或路径拼成 shell 命令。普通操作使用 Git Bash；百度 CLI 需要 WSL，桥接层负责将 Windows 本地路径映射为 WSL 路径，不能把 Windows 路径原样传给 Linux 程序。

非敏感配置由 `site.config.json` 提供：站点 URL、下载 URL、R2 bucket/account、Pages project/生产分支、百度 WSL distribution。私密凭据通过环境或系统凭据提供。普通本地准备不要求云登录。

## 2. prepare：准备新增或更新

```bash
# 新增书籍；默认不启用百度分享
npm run book -- prepare --id example-book --epub 'D:/Books/example.epub' --model '模型显示名称'

# 已验证百度能力后，为本次计划启用可选备用分享
npm run book -- prepare --id example-book --epub 'D:/Books/example.epub' --model '模型显示名称' --baidu optional

# 更新现有书籍，必须显式声明，防止误覆盖
npm run book -- prepare --id example-book --update --epub 'D:/Books/example-new.epub' --model '新模型显示名称'
```

参数：

| 参数 | 规则 |
| --- | --- |
| --id | 必填，匹配 `[a-z0-9]+(?:-[a-z0-9]+)*`，最长 80 字符；新增时不得已存在 |
| --epub | 必填，本地可读的 EPUB 文件；不接受远程 URL |
| --model | 必填，非空模型显示名称；保持维护者输入，不猜测供应商或版本 |
| --kind | 默认为 ai-translation；transcription 表示中文出版物转录，此时不得提供 model |
| --update | 仅允许更新已存在的同一 ID；未带此参数时遇到已存在 ID 就失败 |
| --baidu | `off` 或 `optional`，默认 `off`；optional 失败时允许仅发布 R2 |
| --json | 返回结构化结果；不影响行为 |

更新时如已有百度备用链接但未启用本次分享，报告明确显示“新译本将移除原备用链接”。不会让旧链接继续指向另一个 EPUB。不从同名标题推断更新目标。

执行内容：

1. 校验输入，读取现有书目及站点配置，保存基线指纹。
2. 将 EPUB 复制到 `.local/plans/<plan-id>/`，计算完整 SHA-256，提取元数据和封面。
3. 生成候选书目；与已发布书目合并到隔离的构建目录，不修改正式书目。
4. 生成供审核的静态页面和索引、变更报告、计划清单，标记为 `prepared`。
5. 输出计划编号、文件大小/哈希、提取结果、模型、分类、更新差异、百度策略和警告。

快照必须包含本次构建所需的站点源码、锁文件/依赖指纹及候选数据。之后原始 EPUB 的移动或修改不影响此快照；实施时不得重新读取原文件进行发布。

计划清单至少包含：格式版本、plan ID、操作、book ID、EPUB 哈希/大小、模型、元数据/封面摘要、书目基线指纹、源码与依赖指纹、站点配置、R2 key、百度策略和审核内容摘要。plan ID 使用随机标识；摘要覆盖实际内容，不能只用时间戳判断是否变化。

**没有远程写入**：不上传 R2、不请求百度创建分享、不部署 Pages、不推送 Git。

## 3. preview / validate / status：本地审核

```bash
npm run book -- preview --plan p-example
npm run book -- validate --plan p-example
npm run book -- status --plan p-example --json
```

- `preview` 仅监听 `127.0.0.1`，默认端口 4321，冲突时明确提示；输出首页和目标书籍详情页地址。
- 预览中的下载入口标记为“发布后可用”，不把草稿 EPUB 放到公开目录。百度入口为占位说明，不能虚构真实分享链接。
- `validate` 检查 EPUB、提取数据、内部链接、搜索索引、构建、下载 URL 格式及快照完整性；不要求访问尚不存在的远程 EPUB。
- `status` 返回计划阶段、变更摘要、检查结果、阻塞项及已完成的远程步骤，不输出凭据。

审核关注：封面、书名、作者、简介、分类、模型、手机布局、目标文件，以及本次是否需要百度公开分享。下载链接和提取码在发布后生成，属于审核时已说明的预期变化。

## 4. 人工确认

AI 向维护者呈现计划编号、变更摘要、预览地址和百度策略，等待对该计划的明确发布确认。准备、启动预览、等待时间、生成本地文件或旧计划的确认均不等于本次发布授权。

不设计自动确认命令或通用 `--yes` 绕过此步骤。CLI 是命令行工具，无法自行验证聊天授权；AI 负责在收到明确确认后才调用发布命令，人工直接执行 publish 则表达执行意图。CLI 仍需验证计划摘要和过期状态，不能靠交互提示替代内容校验。

计划内输入被改动，或工作区源码、依赖、站点配置、书目基线改变后，旧计划标记 `stale`，必须重新 prepare、preview 并确认；不自动更新已审核内容。原始输入路径的 EPUB 已复制到快照，原文件后续变化不会改变此次发布内容。

## 5. publish：确认后执行

```bash
# 仅在收到对此计划的明确确认之后执行
npm run book -- publish --plan p-example
```

步骤与成功条件：

1. 获取站点发布锁，复查本地基线、计划完整性和验证结果，检查凭据可用性。首版假定只有一台维护电脑，不声称本地锁能防止跨设备并发。
2. 上传快照中的 EPUB 至已确定的 R2 key，设置 MIME、attachment 文件名和 SHA-256 元数据。已有相同对象时核对后复用，不覆盖不匹配对象。
3. 验证 S3 元数据，并经公开下载域名实际读取文件、核对 SHA-256；R2 验证失败就停止，不部署页面。不要在上传前探测新公开 URL，以免缓存 404。
4. 若策略为 optional，调用已验证的百度 CLI 上传同一快照文件并创建永久分享，记录真实链接、提取码及关联文件哈希。失败则保留错误记录，以 null 写入新备用入口并继续；不能复用旧译本分享。阶段结果不确定时先查询或核实，不能立即重复创建。
5. 把真实下载结果和发布时间填入发布快照，在同一源码、依赖和输入下完成最终构建。允许与预览不同的字段仅为下载结果、发布时间及发布标识；任何其他内容变化都停止并重新审核。
6. 通过 Wrangler Direct Upload 部署最终 `dist`，显式指定已配置的生产分支。将 plan ID 写入发布信息，并在静态产物中生成不含凭据的 `release.json`。
7. 确认部署完成，检查生产 `release.json` 的 plan ID、详情页和主下载。成功后将最终书目和封面写回正式目录，保存发布日志。报告本地变更尚待提交，默认不 commit 或 push。

`release.json` 仅含 plan ID、构建标识和书目摘要，不含本地路径、账号或 Token。验证线上发布标识时避开浏览器/CDN 旧缓存；标识不符属于“结果未确认”，不能宣称上线成功。

结果清晰区分：

| 状态 | 含义 |
| --- | --- |
| published | R2、生产部署及上线检查成功 |
| published_with_warnings | 已上线，但可选百度步骤失败；主下载正常 |
| failed | 已知失败；报告停在哪一步及仍存在的远程资源 |
| uncertain | 部署或分享请求已发送但无法确认结果；先核实远程状态 |

发布记录保存开始时间、审核摘要、每步结果、R2 key、百度实际结果、Pages deployment ID、线上校验结果和警告；不存储授权码或云凭据。

## 6. 失败与恢复

```bash
npm run book -- status --plan p-example --json
npm run book -- publish --plan p-example --resume
```

| 情况 | 恢复约定 |
| --- | --- |
| R2 上传中断 | 核对目标对象；一致则复用，缺失则重传同一快照；页面仍指向原发布 |
| 百度明确失败 | 按 optional 策略继续，报告备用渠道缺失，不误报分享成功 |
| 百度结果不确定 | 记录远程路径及返回标识，先核实；无法核实时跳过本次可选渠道，不盲目重复创建 |
| 构建失败 | 停止部署，保留上传结果；修复代码后重新准备并确认，不把新代码塞入旧计划 |
| Pages 明确失败 | 保留旧站点及新文件；恢复时复用已上传文件和已取得的分享链接 |
| Pages 返回超时 | 用部署记录和生产 release.json 核实；未核实前不直接重复部署 |
| 线上已成功，本地回写失败 | 日志标为待本地同步；resume 从发布快照恢复书目，不重新上传或部署 |
| 新计划已经上线 | 旧计划不能 resume 覆盖新状态，重新准备变更 |

同一有效计划在相同目标上已发布时，再次调用返回既有结果，不创建新的分享或部署。`--resume` 只恢复已确认计划，不能接受新增书籍、修改模型或改变百度策略。

部署成功后若发现展示问题，可由维护者确认后使用 Pages 的上一成功部署恢复页面；对应旧对象在保留期内仍可下载。恢复后以该部署保存的书目快照同步本地状态，避免线上与本地分叉。这是故障恢复，不是面向读者的多版本功能。

默认不自动删除 R2、百度文件或分享链接；孤立资源在报告中列出，后续清理需单独明确操作范围。

## 7. 输出和退出码

所有命令支持 `--json`，使用统一信封：`schemaVersion`、`command`、`planId`、`status`、`data`、`warnings`、`error`。机器输出写 stdout，进度写 stderr；不将 ANSI 颜色或秘密混入 JSON。

| 退出码 | 含义 |
| --- | --- |
| 0 | 命令成功，包括带可选百度警告的成功发布 |
| 2 | 参数或 EPUB 输入错误 |
| 3 | 计划过期、快照变化或书目冲突 |
| 4 | 本地构建或验证失败 |
| 5 | 必需的云认证、上传或部署失败 |
| 6 | 远程结果不确定，需核实或恢复 |
| 7 | 目标站点已有发布进程 |

CLI 启动长时间 publish 时输出当前阶段；最终报告必须给出真实上线 URL、主下载验证结果、百度结果、下一步或恢复命令。不可仅凭进程退出或上传返回值声称全部成功。

## 8. 批量维护

第一版允许连续 prepare 多本书，再执行：

```bash
npm run book -- bundle --plans p-one p-two
npm run book -- preview --plan p-bundle
npm run book -- publish --plan p-bundle
```

`bundle` 是本地操作：只合并同一基线、配置与源码的计划，拒绝重复 book ID，生成一个新的独立快照及完整变更报告；必须预览并确认新的 bundle ID。子计划的确认不能代替整批确认。整批只部署一次 Pages；任一本 R2 失败，整批不部署，已上传对象留待恢复。逐书百度仍按 optional 处理。

当前已实现的批量入口是 prepare --manifest，直接生成整批快照，无需 bundle。上方 bundle 属于未来合并已有独立计划的设计，目前未实现，也未放入帮助文本。
